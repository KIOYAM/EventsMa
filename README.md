## Method and confidence
The documents combine public product claims with detailed proposed engineering specifications: feature blueprints, data contracts, illustrative API contracts, operational scenarios, tests, security and reliability considerations, and evidence-collection templates. Illustrative schemas and endpoints are **not** claims about private competitor internals. Confirmed facts, inferred behavior, proposed architecture, and unknowns should remain clearly separated.

## Important limitation
A true implementation-level reverse engineering pass requires lawful, authorized observation of the product, including screen recordings or screenshots and controlled input/output experiments. Public websites and app listings cannot establish private source code or undocumented APIs. These guides are detailed independent specifications, not assertions of unauthorized access.
